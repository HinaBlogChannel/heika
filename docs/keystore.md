# キーストアの形式

`heika wallet` のキーストア（既定では `keystore.age`）の形式を定める。heika がなくても読み書きできるように、ほかの道具から扱うときの決まりをここにまとめる。扱いの方針と理由は [secrets.md](secrets.md#キーストア) にある。

## 暗号化

ファイル全体は [age v1](https://age-encryption.org/v1) の形式で、パスフレーズで暗号化する（scrypt の受取人）。`age -d` や `rage -d` で開け、`age -p` で暗号化したものも読める。

- 受取人は scrypt の1つだけ。ほかの受取人と混ぜたものや、公開鍵あてのものは読まない。age の決まりと同じである。
- heika は scrypt の作業係数を 2^18 で書き、2^22 まで読む。
- ASCII armor（PEM のような枠）は書かず、読まない。

## 中身

復号した中身は UTF-8 のテキストで、改行は LF だけ。秘密1つにつき1つのブロックにし、ブロックの間は空行1つで区切る。最後のブロックも改行で終える。秘密が1つもないキーストアは、空のテキストである。

```text
Heika-Keystore-Version: 1
Secret-Type: Mnemonic
Secret: <単語> <単語> … <単語>
Harvest-Secret: <単語> <単語> … <単語>
Account: mainnet 0 main
Account: testnet 0 test

Heika-Keystore-Version: 1
Secret-Type: Private-Key
Secret: <秘密鍵の16進>
Harvest-Secret: <単語> <単語> … <単語>
Account: mainnet cold
```

ブロックの各行は `キー: 値` で、キーと値はコロンと空白1つで区切る。キーは大文字と小文字を区別する。行の順は決めない。

| キー | 数 | 値 |
| --- | --- | --- |
| `Heika-Keystore-Version` | 1つ | `1`。ブロックごとに書く |
| `Secret-Type` | 1つ | `Mnemonic` か `Private-Key` |
| `Secret` | 1つ | 秘密そのもの。下を参照 |
| `Harvest-Secret` | 0か1つ | ハーベストの鍵を導出するニーモニック。下を参照 |
| `Account` | 0個以上 | この秘密から使うアカウント。下を参照 |

- `Account` 以外のキーが同じブロックに2つあれば、読まずにエラーにする。
- 知らないキーの行は読み飛ばす。版を上げずにキーを足せるようにするためである。今の heika は、知らないキーを書き戻さない。
- `Heika-Keystore-Version` が `1` でないブロックがあれば、キーストア全体を読まない。中身の意味を変えるときは版を上げる。

### Secret

- `Mnemonic`: BIP 39 の英語の単語リストの単語を、小文字のまま空白1つで区切ったもの。12、15、18、21、24語で、チェックサムが合うもの。パスフレーズを空にして計算したシードではなく、単語そのものを入れる。
- `Private-Key`: Ed25519 の秘密鍵（32 バイト）の16進、64文字。heika は大文字で書き、大文字も小文字も読む。

### Harvest-Secret

ハーベストに使うリモートアカウントと VRF の鍵を導出するための、24 語のニーモニック。書き方は `Mnemonic` の `Secret` と同じ。

- heika は、キーストアを書くときに、`Harvest-Secret` のないすべてのブロックに作って入れる。ハーベストに使うかどうかに関わらず入れるので、あることからは、ハーベストしているかどうかはわからない。
- 一度入れたら書き換えない。書き換えた時刻が、チェーンで鍵をリンクした時刻と並べば、どのアカウントのものかの手がかりになるためである。鍵を作り直すときは、下の作り直しの番号を上げる。
- 鍵は、このニーモニックのシードから SLIP-10 の Ed25519 で、`m/44'/<コイン>'/<番号>'/<役割>'/<作り直しの番号>'` で導出する。コインと番号は、同じブロックの `Account` のもの。役割はリモートが 1、VRF が 2 で、アカウントの鍵のパス（4番目が 0）とは重ならない。作り直しの番号はふだん 0。heika だけの約束で、公式ウォレットにはない。
- シードは、`Mnemonic` のアカウントなら、アカウントと同じ BIP 39 のパスフレーズをかけて計算する。パスフレーズごとに別の鍵になるので、キーストアを開けても、隠したウォレットのリンクはたどれない。`Private-Key` のアカウントなら、パスフレーズは空で、番号は 0 として導出する。
- 古い heika は `Harvest-Secret` を知らないので、書き直すと消える。そのあと新しい heika で書くと別のものが入り、それまでのハーベストの鍵とは合わなくなる。

### Account

```text
Account: <ネットワーク> <番号> <ラベル>   （Mnemonic のとき）
Account: <ネットワーク> <ラベル>          （Private-Key のとき）
```

- ネットワークは `mainnet` か `testnet`。
- 番号は、ニーモニックから導出するアカウントの番号で、0 から 2^31 - 1 までの10進。先頭に 0 を付けない。鍵は SLIP-10 の Ed25519 で、公式ウォレットと同じ `m/44'/<コイン>'/<番号>'/0'/0'` で導出する。コインはメインネットが 4343、テストネットが 1 である。
- ラベルは行の残り全部で、空白を含められる。1文字以上で、制御文字を含まず、前後に空白がないもの。キーストア全体で重ならない。
- BIP 39 のパスフレーズはどこにも書かない。heika で `--expert` を付けて聞かれたときに入れたものを使い、空なら公式ウォレットと同じ鍵になる。

## 互換性

- `Heika-Keystore-Version: 1` の形は、これから先の heika でも読めるようにする。
- 手で書き換えたキーストアも、この形に従っていれば読める。heika が書き直すと、行の順や16進の大文字小文字はこの文書の例の書き方にそろい、知らないキーの行は消える。
